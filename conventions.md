Файл живой: меняем по мере принятия решений. Если что-то тут устарело — правим сразу.

## Цель

Чат-приложение в стиле Telegram: список каналов слева, сообщения в канале справа. Требование преподавателя — три клиента: веб-браузер, мобилка, десктоп.

## Архитектура

- **Бэкенд** — этот проект (папка `chatapp`), REST API + авторизация.
- **Фронтенд** — отдельный проект на Flutter: веб + мобилка из одной кодобазы.
- **Десктоп** — пока не решено (TBD). Кандидаты: Flutter Desktop (тот же код, что и мобилка), либо отдельная обертка позже. Разбираемся, когда заработает веб.

## Стек бэкенда

Зафиксирован в `build.gradle.kts`:

## Авторизация

- Идентификация пользователей обязательна — без неё нет смысла в каналах и авторах сообщений.
- Делаем на Spring Security.
- Формат: JWT в заголовке `Authorization: Bearer ...` (решено).

## Предварительная модель данных

- `User` — id, username (уникальный, для логина), пароль (хэш), отображаемое имя.
- `Channel` — id, название, тип (личный диалог / групповой), участники (связь many-to-many с User).
- `Message` — id, channel_id, author_id, текст, время отправки.

## API — общие правила

- Префикс `/api`, версия в пути пока не нужна (`/api/v1` — когда понадобится).
- JSON в обе стороны, имена полей — `camelCase` (как принято в Kotlin/Java-мире и удобно парсить во Flutter).
- DTO для входа/выхода на границе API, entity не отдаем наружу.
- Время — ISO 8601 в UTC.
- Ошибки — понятный JSON с кодом и сообщением, не голый стектрейс.

## Правила разработки

- Комментарии в коде — только где действительно неочевидно, код и имена должны объяснять сами себя.
- Новые зависимости — через обсуждение, не молча.
